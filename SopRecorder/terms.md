## Screenshot capture and input triggers

The current recorder defaults to a selected display, using the primary or last valid display selection. Display mode captures the whole selected display across applications. An optional window mode targets one selected window; it does not necessarily include other windows or separate dialogs belonging to that application. Check the selected target before recording.

While recording, the enabled automatic workflow can capture an initial image and additional screenshots triggered by mouse clicks, the start of typing bursts, and Tab or Shift+Tab navigation. Manual capture is also available. The application processes mouse and keyboard events to identify these triggers. Its current source does not create a raw typed-text or keystroke transcript, but text visible on the screen can appear in a screenshot. Automatic capture can be unavailable or fail, and a capture may miss an action or include information beyond the step you intended to document.

## Workflow details and file locations

The session can include the task name, goal, starting point, completion description and step notes you enter. Recorded evidence includes capture source and trigger, step order, timestamps with UTC offset, active and elapsed timing, and any reviewed file locations and verification status. Window selection reads application-window titles and process information to identify and validate the target. These details and the image content can identify people, systems or work even when no person's name was intentionally entered.

Verified full file-location recording is limited to the built-in text-viewer workflow: while recording a display, you choose the supported local .txt file, and the viewer records the file location associated with the file it opens. This does not automatically verify ordinary file opens in Explorer, Office, a browser or other applications. Locations you enter or edit during review are marked as manual rather than independently verified. The opened source file itself is not bundled into the export, although its displayed contents may appear in screenshots.

Start-to-stop elapsed time includes pauses and any stopped review gap. Active recording time and intervals between retained images exclude those inactive periods. Intervals can include idle time, omitted screenshots or unrecorded activity and are not a measurement or certification of work effort.

## Local files and ZIP exports

The current recorder saves working screenshots and temporary capture or file-location metadata in a session folder under the Windows temporary location. It stores selected capture preferences under the user's local application-data location. Task details and notes remain in memory until export. Export before closing or starting a new task if you need to retain the session; temporary files are not a reliable recovery copy.

After you stop and confirm your review, ZIP export includes procedure.md and the retained PNG screenshots. The Markdown contains the retained task details, notes, source and trigger information, timing and reviewed file locations. Images include capture-time information in a footer. These exports are ordinary readable files without application-added encryption. Review the destination and any overwrite confirmation, and protect saved copies appropriately.

Removing a step excludes it from a new export but does not immediately erase its working screenshot from temporary storage. Normal closing or starting a new task attempts to remove the session folder; failed cleanup or an interruption can leave files behind. Neither removal nor cleanup promises secure deletion. Existing exported copies remain separate and are not automatically changed by later session edits.
